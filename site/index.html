Desktop API client for Windows

No Cloud. No Bloat. Just Requests.

Fuseprobe is a local-first desktop API client for deliberate request work. A Tauri shell, a React interface, and a Rust request core. There is no workspace to join, no account to create, and no telemetry to opt out of.

Positioning

A focused request workbench, not a platform

Fuseprobe does a narrow job properly. Knowing what it leaves out is as useful as knowing what it does.

What it does

  • Sends HTTP requests without any cloud service in the path
  • Inspects formatted, header and raw responses side by side
  • Tests auth and header combinations quickly
  • Keeps sensitive request activity off disk unless you allow it
  • Runs with strict security defaults on local machines

What it is not

  • Not a cloud workspace
  • Not a team collaboration suite
  • Not a Postman clone
  • Not a browser tab pretending to be an app
Features

What you get in the window

Offline first

Runs locally with no cloud dependency. Close your network and the app still opens, still works, still holds your presets.

Rust request core

Request validation, policy enforcement, response classification and history redaction all live in a separate Rust crate rather than in the interface.

Formatted response workflow

Switch between the formatted body, the response headers and the raw payload without losing your place.

Auth presets

No Auth, Bearer, Basic, API Key header and API Key authorization, ready to switch between while you probe an endpoint.

API templates

Open-Meteo, Microsoft Graph, GitHub, JSONPlaceholder, HTTPBin and ReqRes are preloaded so there is something to send on first launch.

Session-first history

Request history stays in memory. It reaches disk only when you deliberately turn persistence on.

Three languages

English, German and Hungarian interface copy, including localized warnings and response metadata, with your choice remembered.

Low-glare shell

Calmer syntax colors, softer bright text and a denser first screen, tuned for looking at responses all day.

Security defaults

Strict on first launch, loosened only by you

Every one of these is a deliberate product decision rather than a feature that has not been built yet. Each can be changed, and the risky ones ask you to confirm first.

Unsafe mode and local targets

OFF

localhost, private IP ranges, link-local targets and metadata-style endpoints

BLOCKED

Hostnames that cannot be resolved during request validation

FAIL CLOSED

History persistence to disk

OFF

Switching on a risky setting

NEEDS CONFIRMATION

A hostname that fails to resolve does not quietly bypass the target policy. It fails closed, which is the behaviour you want when the thing you are probing is not where you expected it to be.

Install

Get the Windows build

The intended path is the release installer. Building from source is documented in the repository and is meant for contributors.

  1. Open GitHub Releases and pick the latest tag.

  2. Download the Fuseprobe_*_x64-setup.exe asset.

  3. When a companion *.sha256 asset is present, verify the installer hash before you pass the file on to anyone else.

  4. Install, then launch Fuseprobe from the Start menu.

One thing to expect

Windows installers are not code signed yet, so SmartScreen may warn about an unknown publisher on first run. The published *.sha256 file is there so you can confirm you have the file that was actually built and released.
